# Research: 주행 이벤트 판정과 펫 감정 결정 코어

Phase 0 결과. 계획 단계에서 정해야 했던 설계 결정과 근거를 기록한다. 기술 맥락의 `NEEDS CLARIFICATION` 은 없고,
확인이 필요한 값 2건은 마지막 "미결 항목"에 모았다.

## R1. 시나리오는 어떤 형식으로 쓰나

- **Decision**: Kotlin 데이터 모델 + DSL(`scenario("demo-commute") { at(8_000) { ... } }`)로 정의한다. JSON 파일 로더는 이 기능에서 만들지 않는다.
- **Rationale**: 스펙(FR-020)은 "시간순으로 적힌 시나리오를 재생"만 요구하고 파일 형식은 정하지 않았다. DSL 이면 새 의존성(직렬화 플러그인 등)과
  Gradle 위험이 없고, 컴파일 타임에 오타가 잡히며, JVM 테스트에서 바로 쓴다. 개발 명세서가 JSON 을 언급했지만 JSON 이 필요한 이유(비개발자 편집)는
  지금 없다.
- **Alternatives considered**: kotlinx-serialization(플러그인 버전을 Kotlin 2.2.10, AGP 9.5.0 과 맞추는 검증이 필요), `org.json`(JVM 단위 테스트에서
  Android 스텁이 먼저 잡혀 동작이 불안정할 수 있음). 나중에 JSON 이 필요해지면 `Scenario` 모델은 그대로 두고 로더만 추가한다.

## R2. 속도와 방향을 하나의 신호로 묶을까

- **Decision**: 분리한다. `Speed(speedMps)` 와 `Heading(headingDeg)` 를 별개의 `RawSignal` 로 둔다.
- **Rationale**: API 전수 조사에서 차량 속도는 Pleos SDK 에 없고(AAOS 표준 값 사용 예정), 방향은 조향각 또는 위치 방위각에서 오는 등 출처가 서로 다르다.
  개발 명세서의 `Location(speedMps, bearingDeg)` 한 묶음은 두 값이 같은 출처에서 같은 시각에 온다고 가정한다. 분리하면 출처를 바꿔도 엔진이 변하지 않는다(FR-022).
- **Alternatives considered**: 명세서의 `Location` 유지(출처 교체 시 엔진 수정 필요, 기각).

## R3. 가속도 계산과 평활화

- **Decision**:
  - 앞뒤 가속도: 연속한 `Speed` 샘플에서 `(v_t − v_{t−1}) / Δt`. 속도에 지수이동평균(가중 0.4)을 먼저 건다.
  - 옆 가속도: 연속한 `Heading` 샘플의 방위 변화율(각도 차를 −180~180° 로 정규화해 라디안으로 변환) × 최신 속도.
    방향은 평활화 전에 직전 값 기준으로 펼쳐서(unwrap) 지수이동평균을 건다.
  - 각 축에서 임계값을 2회 연속 넘을 때 확정한다. 임계값 아래 샘플이 한 번 오면 연속 횟수를 0으로 되돌린다.
  - 샘플 간격이 2초를 넘거나 속도가 없으면 그 샘플을 버리고 기준선(직전 샘플)도 초기화한다.
- **Rationale**: 스펙 FR-003~005 와 개발 명세서 3장의 공식을 그대로 따른다. 방위각은 359→1 에서 튀므로 정규화가 필수다.
- **Alternatives considered**: 속도 변화율 대신 가속도계 사용(어떤 SDK 에도 가속도, 요레이트 API 가 없음). 조향각 기반 옆 가속도(`v²·tanδ/L`)는 축거 상수가 필요해 이 기능에서는 제외하고,
  입력 타입(`Heading`)만 맞춰 두어 나중에 다른 입력으로 바꿀 수 있게 한다.

## R4. 이벤트 세기(0~1) 정규화

- **Decision**: `intensity = clamp((|a| − 임계값) / (A_MAX − 임계값), 0, 1)`, `A_MAX` 초안 7.8 m/s²(약 0.8g). 판정을 확정한 샘플의 값으로 계산한다.
- **Rationale**: 스펙은 세기가 0~1 이라고만 하고 공식을 정하지 않았다. 데모 값(급제동 약 6.9, 급커브 약 7.3 m/s²)이 0.77~0.87 로 나와 캐릭터 표현 범위(`s` 가 클수록 강한 반응)에 자연스럽게 들어간다.
- **Alternatives considered**: `|a| / A_MAX`(임계값 근처에서 이미 0.5 이상이 되어 약한 급가속도 큰 반응이 됨). 확정 후 구간의 최댓값 사용(출력 시점이 늦어짐).
- **Status**: `A_MAX` 는 초안이다. 테스트 주행 후 조정한다(`EngineConfig`).

## R5. 쏠림 방향의 정의

- **Decision**: `Direction4` 는 "몸이 쏠리는 쪽"이다. 급제동 → `FRONT`, 급가속 → `BACK`. 급커브는 우회전(방위각 증가) → `LEFT`, 좌회전(방위각 감소) → `RIGHT`.
- **Rationale**: 개발 명세서 5-2, 5-8 의 규칙("운전자가 몸으로 느끼는 쏠림", 좌회전 → 오른쪽 패널, 우회전 → 왼쪽 패널)과 같다.
- **Alternatives considered**: 꺾는 방향을 그대로 쓰기(명세서 규칙과 반대, 기각).
- **미결**: 아래 "미결 항목 1".

## R6. 시간과 결정성

- **Decision**: 엔진은 벽시계를 읽지 않는다. 시간은 각 신호의 `timestampMs` 와 `advanceTo(ms)` 로만 진행한다. 감정 지속 시간 만료, 재발 간격, 차선 변경 직전 3초 확인이 모두 이 시간을 쓴다.
  같은 시각의 신호는 입력 순서를 유지한다.
- **Rationale**: SC-002(100번 재생해도 같은 결과)와 JVM 테스트의 빠른 실행을 보장한다. 목업은 속도·방향을 10Hz 로 풀어 보내므로 감정 만료가 시간 진행에 맞춰 일어난다.
- **Alternatives considered**: `System.currentTimeMillis()` 또는 코루틴 `delay` 기반 만료(테스트가 느리고 비결정적, 기각).

## R7. 주행(Trip) 수명주기

- **Decision**: 주차 상태 입력의 변화로 판정한다(FR-024).
  - 초기 상태는 "알 수 없음". 첫 입력이 "주차 아님"이면 주행 중 시작으로 보고 이벤트 없이 Trip 을 시작한다(앱이 주행 중에 켜진 경우). 출발과 벨트 체결 이벤트는 발생시키지 않는다.
  - 주차 → 주차 아님: 출발 이벤트와 새 Trip. 이후 경고가 켜졌다가 꺼질 때만 벨트 체결.
  - 주차 아님 → 주차: 속도가 0 이 될 때까지 도착 대기. 속도 0 이 되면 도착 이벤트와 Trip 종료.
  - Trip 이 없을 때 들어온 급가속 등은 무시한다(기록하지 않음).
- **Rationale**: 스펙 Edge Cases("주행 시작 전에 들어온 벨트 경고 해제는 체결로 치지 않는다", "주차 상태여도 속도가 0이 아니면 도착이 아니다")를 만족하는 최소 규칙이다.
- **Alternatives considered**: 주행 중에 앱이 켜지면 출발 이벤트를 만든다(거짓 인사가 나오므로 기각).

## R8. 출력 방식

- **Decision**: 동기 코어 `EngineCore.process(signal)` 가 결과(`EngineStep`: 이벤트 목록과 최신 `PetOutput`)를 돌려주고, 코루틴 래퍼 `DrivingEngine` 이 `Flow<RawSignal>` 을 받아 `StateFlow<PetOutput>` 과 `SharedFlow<DrivingEvent>` 로 내보낸다.
  `PetOutput` 은 감정, 강도, 방향, 모션 등급, 방향지시등 상태, 시각을 담고, 주행 제한 상태가 바뀌면 이벤트가 없어도 새로 낸다.
- **Rationale**: 핵심 로직은 코루틴 없이 테스트하고, 래퍼는 `runTest` 로 얇게 검증한다. UI 는 `StateFlow` 하나만 구독하면 된다(헌장 II, III).
- **Alternatives considered**: 처음부터 Flow 변환 연산자로 구성(단위 테스트가 복잡해지고 같은 시각 순서 보장이 어려움).

## R9. 도착 이벤트의 감정

- **Decision**: 도착 이벤트 시점에 계산한 점수(합산 후 0~100 으로 자른 값)가 80 이상이면 기쁨, 아니면 감정을 바꾸지 않는다.
- **Rationale**: FR-009. 마지막에만 자르는 규칙(FR-014)과 일치한다.

## R10. 방향지시등 상태 전달

- **Decision**: 방향지시등 상태(꺼짐/좌/우)는 이벤트와 별개로 `PetOutput.turnSignal` 에 항상 최신값을 싣는다. 점멸 박자는 SDK 가 주지 않으므로(조사 결과) 이 기능에서 다루지 않는다.
- **Rationale**: FR-019. 윙크의 380ms 주기는 그리는 쪽(`:pet`)이 자체 타이머로 만든다.

## 미결 항목

1. **[확인 필요] 방위각 부호와 데모 기대값.** 개발 명세서 9장은 방위각 +30° 에서 "오른쪽으로 찌그러짐"이라고 적었다. 그런데 방위각은 시계 방향이 증가이고(+30° = 우회전),
   5-8 의 규칙은 우회전 → 왼쪽 패널이다. 이 계획은 5-8 의 규칙을 따르며(R5), 데모 시나리오 테스트는 이벤트 종류, 순서, 점수만 단정하고 방향은
   별도 단위 테스트로 확인한다. 데모 영상의 기대 동작(왼쪽/오른쪽)은 기획자 확인 후 확정한다.
2. **[확인 필요] 세기 정규화 상한 `A_MAX`(7.8 m/s²).** 스펙에 값이 없어 초안으로 정했다(R4). 캐릭터 표현 튜닝 때 조정한다.
