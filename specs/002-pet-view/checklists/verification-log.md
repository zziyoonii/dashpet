## 발견한 문제와 관찰

1. **재생이 설계보다 느리고 표시 시각이 어긋난다.** 패널 시각이 실제 경과 시간의 약 85~90%로 흐른다(스크립트 15초 → 표시 0:13, 47초 → 0:41). `MockSignalSource`(REAL_TIME)의 상대 `delay`와 `DemoViewModel` 경과 타이머(`delay(100)` 루프)가 각각 반복마다 지연을 누적하고 서로 독립이라서, 이벤트 시각, 표시 시각, 실제 시간이 모두 어긋난다. 영상이 설계(55초)보다 길어진다.
2. **컨트롤이 작다.** 2560x1440 화면에서 컨트롤 버튼과 패널 글자가 매우 작게 보인다(글자는 12sp 이상이지만 차량 화면 기준으로 터치 대상이 작다). Pleos UI 가이드는 큰 터치 대상을 요구한다.
3. **앱이 가려졌다 돌아오면 상태가 초기화된다.** 위 J 참고. 이 데모 화면에서는 문제가 아니지만 제품 화면에서는 상태 저장 전략이 필요하다(설계 가이드: 프로세스 재생성에도 진행 상태 복원).

## 주의

- 에뮬레이터 창은 사용자의 화면에 열려 있어 사람이 직접 만질 수 있다. 자동 캡처 중에 조작하면 결과가 어긋난다. 재촬영할 때는 에뮬레이터를 건드리지 않는다.
- 스크린샷은 `/tmp/dashpet_shots/`(임시)에 있고 저장소에는 올리지 않았다.

## 윙크, 외형, 배경 감정 구현 확인 (2026-11-15, 에뮬레이터 Pleos Connect v2.1.0)

대상: US4(윙크), US5(외형), US7(배경 감정), 이름 라벨. 단위 테스트는 `:pet` 152개(이번 추가 46개), `:app` 10개, `:engine` 135개, `:signal` 32개 모두 통과, 실패 0.

앱에는 배경 감정과 방향지시등을 직접 넣는 입력이 아직 없어서(이후 기능), 화면 확인은 **임시 확인 코드**로 했다. `HomeScreen` 에서 `files/ambient` 파일 값을 읽어 `PetController.setAmbient` 와 `applyOutput(방향지시등)` 을 부르는 코드였고, 확인 뒤 `git checkout` 으로 되돌렸으며 커밋하지 않았다.

- 확인하지 못한 것: 정적 모드의 비 우비 화면(프리뷰만 추가, 에뮬레이터 미확인), 모션 줄이기, 윙크 380ms 주기의 실제 시간(캡처 간격이 거칠어 단위 테스트로 대신), 배경 감정이 들어간 상태의 fps. 앞선 표의 G, H, F, I, J 도 여전히 미확인이다.
- 환경 메모: 에뮬레이터가 한 번 비정상 종료돼서(`adb: device offline`, 크래시 기록 `crashpad`) 다시 띄웠다. 앱 문제인지 에뮬레이터 문제인지는 확인하지 못했다. [확인 필요]
- 자동 점검(T071): `pet/src/main` 에 반복 애니메이션 API(`rememberInfiniteTransition`, `animate*AsState`, `Animatable`, `Handler`, `Timer`)가 없고, `withFrameNanos` 는 `PetView` 의 루프 한 곳뿐이며, 벽시계(`System.currentTimeMillis` 등)와 `ai.pleos`, `:signal` 구현체 import 가 없다. `pointerInput`/`clickable` 도 없다.

## 남은 확인 H, I, G 회전 (2026-11-15, 에뮬레이터, `main` 빌드)

`main`(001~004 포함) 빌드로 확인했다. 이제 앱이 말하기 로그(`Speech`)를 남기므로 H 는 회마다 나온 이벤트 순서를 로그로 비교했다.
