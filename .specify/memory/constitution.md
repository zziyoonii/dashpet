# DashPet Constitution

## Core Principles

### I. 주행 안전 우선 (NON-NEGOTIABLE)
- 주행 상태는 플랫폼이 알려주는 주행 제한 상태(`CarUxRestrictions`)를 1순위로 따른다.
  속도와 주차 브레이크는 보조 신호일 뿐이며, 지역별 하드코딩 분기를 두지 않는다.
- 제한이 걸린 상태(정차 중, 주행 중, 상태를 알 수 없음)에서 캐릭터는 정적 포즈와 색 변화,
  한 문장 음성만 쓴다. 터치는 비활성화하고 팝업은 띄우지 않는다.
- 제한 상태에서 MUST NOT: 반복 모션(숨쉬기, 깜빡임, 점멸), 몸이 출렁이는 물리 반응,
  파티클, 화면을 덮는 표현. 풀 모션은 제한이 풀린 주차·정지 상태와 도착 후 리플레이에서만 쓴다.
- 모션은 등급(A: 정적, B: 일회성 짧은 전환, C: 풀 모션)으로 관리하고, 등급 판단은 한 곳에서만 한다.
  B 등급은 심사 허용 여부가 확인되기 전까지 기본 꺼짐이다.
- `distractionOptimized` 는 주행 중 보여야 하는 메인 Activity 에만 선언한다. 입력이 필요한 화면은
  선언하지 않고 주차·정지 중에만 연다.
- 근거: 이 앱의 공모 분야는 "안전 운전"이다. 운전자의 시선을 끄는 앱은 컨셉과 심사 기준 모두에서 실패한다.

### II. 신호 소스 추상화와 모듈 경계
- 앱 로직은 SDK 를 직접 보지 않고 `VehicleSignalSource` 인터페이스만 구독한다.
  구현체(`MockSignalSource`, `PleosSignalSource`)를 교체해도 이벤트 엔진 이후 코드는 바뀌지 않는다.
- 모듈 의존은 `:app` -> `:pet` -> `:engine` -> `:signal` 한 방향만 허용한다. 역방향과 순환은 금지한다.
- Pleos SDK(`ai.pleos.playground:*`) 의존성과 호출은 `:signal` 에만 둔다.
- 주행 상태 판단과 모션 등급 결정은 `:engine` 에서만 한다. `:app`, `:pet` 은 결과를 받아 그리기만 한다.
- 근거: SDK 일부(Fused Location, ADAS)는 제공 시점이 불확실하다. 경계를 지켜야 목업으로 먼저 개발하고
  나중에 실연결로 바꿀 수 있다.

### III. 테스트 우선 (NON-NEGOTIABLE)
- 이벤트 엔진, 상태 머신, 점수 계산, 모션 등급 게이트는 Android API 없이 JVM 단위 테스트(`src/test`)로 검증한다.
- 구현 전에 테스트를 먼저 쓰고, 실패를 확인한 뒤 구현한다(Red-Green-Refactor).
- 개발 명세서의 목업 시나리오(기대 이벤트 순서와 점수 94)는 회귀 테스트로 고정한다.
- 임계값(가속도, 재발 간격 등)은 한 곳(`EventConfig`)에 모아 테스트에서 주입할 수 있게 한다.
- UI(`PetView`)와 실제 SDK 연동은 에뮬레이터에서 확인하고, 확인한 방법과 결과를 남긴다.

### IV. 플랫폼 접근과 권한 최소화
- 차량 하드웨어와 센서에 직접 접근하지 않는다. 제조사 기능은 Pleos SDK 로, 표준 데이터는 AAOS API 로 접근한다.
  표준 API 사용 허용 여부는 대회 측 확인 전까지 `[확인 필요]` 이다.
- 기능 지원 여부는 차종명이 아니라 Capability 확인(`checkXxxCapabilities`, `isSupported`)으로 판단하고,
  미지원이면 해당 기능만 끈다.
- 권한은 실제로 쓰는 `pleos.car.permission.*` 만 최소로 선언한다. 승인되지 않은 권한 선언과 호출은 금지한다.
- SDK 수명주기를 지킨다: 생성, 초기화, 리스너 등록, 호출, 리스너 해제, `release()`.
  콜백이 끝나기 전에 `release()` 하지 않고, 해제한 인스턴스는 재사용하지 않는다.
- 콜백 스레드는 보장되지 않으므로 UI 갱신은 메인 스레드로 전환한다.

### V. 비밀값과 개인정보 비노출
- 토큰과 키(클라이언트 ID, 시크릿 포함)를 소스와 저장소에 넣지 않는다. 저장이 필요하면 Android Keystore 를 쓴다.
- 위치 기록은 어디에도 저장하지 않는다. 서버에는 레벨, 점수 합계, 코스튬만 보낸다.
- 수집 항목과 목적을 첫 실행에서 한 화면으로 알리고, 동의 버튼 외의 동작을 동의로 취급하지 않는다.
  보험 연계 같은 추가 제공은 별도 동의를 받고 철회할 수 있어야 한다.
- 로그에 민감정보를 남기지 않고, 네트워크는 TLS 1.2 이상을 쓴다.
- Pleos 문서 원문은 저장소에 커밋하지 않는다(요약과 참조만 허용).

### VI. 근거 없는 값 금지
- 문서나 코드로 확인되지 않은 값(해상도, dp, 임계값, 콜백 스레드, 권한 이름)은 추측해서 쓰지 않고
  `[확인 필요]` 로 표시한 뒤 사용자에게 알린다.
- API 시그니처, 권한 문자열, 상수는 기억이 아니라 SDK 레퍼런스와 원문에서 확인한다.
- 문서끼리 충돌하면 최신 릴리즈 노트 > SDK 가이드 > 개발 가이드 > 설계 가이드 순으로 따른다.
- 단종된 기능(LLM SDK)에 의존하는 설계는 대체 경로와 함께 기록한다.

## 플랫폼 및 기술 제약

- 언어는 Kotlin, UI 는 Jetpack Compose 이며 앱은 Activity 기반이다(Car App Library 템플릿 방식은 쓰지 않는다).
  `minSdk` 는 28 이상이다. compile/targetSdk 는 현재 37 이며, 심사 요건과의 일치 여부는 `[확인 필요]` 이다.
- 가로(2 윈도우)와 세로(1 윈도우) 모두 반응형으로 지원하고, 화면 크기가 바뀌어도 상태를 보존하고 복원한다.
  호환 모드나 레터박스로 표시되면 안 된다.
- 최상위 화면에서 Back 이 눌리면 `finish()` 대신 `moveTaskToBack(true)` 로 숨긴다.
  로터리를 지원하지 않는 대신 모든 기능이 터치만으로 동작해야 한다.
- 음성은 오디오 포커스를 요청하고 네 가지 포커스 변경을 모두 처리한다. 음성 앞에는 짧은 선행 무음을 붙인다.
  차량 경고음이 울리는 동안과 직후에는 말하지 않는다.
- 성능 기준(CPU, RAM, 응답 시간)은 `AGENTS.md` 5절을 따른다. 제한 상태에서는 프레임 루프를 멈춰 CPU 를 최소화한다.
- 릴리즈는 정식 서명과 `debuggable` 해제를 지키고, 제출마다 버전을 올린다.

## 개발 워크플로와 품질 게이트

- 작업은 Spec Kit 흐름(`specify` -> `plan` -> `tasks` -> `implement`)을 따른다. 모호한 요구는 `clarify` 로 먼저 푼다.
- 범위는 두 단계로 나눈다: 11/15 프로토타입(물리 반응, 경고 번역, 목업 신호 중심)과 12월 MVP(도착 리포트, 실제 SDK 연결).
  프로토타입 코드는 MVP 로 이어가며 신호 입력부만 교체한다.
- 변경마다 확인 방법을 함께 제시한다: 에뮬레이터, 주행 상태 전환(`adb shell cmd hmg_car_service --service drivingstate
  driving_regulation on|off`, Virtual Console 기어 변경), 제한 시작 시 모션 중단 여부.
- 커밋과 푸시는 사용자가 요청할 때만 한다. 커밋 작성자는 이 저장소의 로컬 git 설정을 따른다.
- 새 기능은 계획 단계에서 이 헌장을 점검한다: 주행 안전, 모듈 경계, 테스트, 권한, 비밀값, 근거 없는 값.

## Governance

- 이 헌장은 다른 개발 관행보다 우선한다. 충돌하면 헌장을 따르거나, 헌장을 먼저 개정한다.
- 개정은 변경 내용과 이유를 기록하고 버전을 올린다. MAJOR 는 원칙의 삭제나 재정의, MINOR 는 원칙이나 섹션 추가,
  PATCH 는 표현 수정이다.
- 계획과 구현 검토에서 헌장 준수를 확인한다. 복잡도를 늘리는 결정은 이유를 남긴다.
- 런타임 개발 지침은 `AGENTS.md`(로컬 전용)와 `ARCHITECTURE.md` 를 참고한다.
