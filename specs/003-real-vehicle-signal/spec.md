# Feature Specification: 실차 신호 연결

**Feature Branch**: `003-real-vehicle-signal`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "실제 차량 신호 연결: VehicleSignalSource 의 실차 구현체. AAOS CarPropertyManager 로 속도(PERF_VEHICLE_SPEED)와 기어 등 표준 데이터를 읽고, CarUxRestrictionsManager 의 ActiveRestrictions 로 주행 제한(Restriction) 신호를 엔진에 공급한다. 에뮬레이터(Pleos Connect, Virtual Console 기어 변경)에서 PetView 가 실제 차량 상태에 따라 움직이거나 정적으로 바뀌어야 한다. 기존 MockSignalSource 데모는 유지한다. 제외: 말풍선/TTS, 온보딩, 리포트, 멀티 윈도우 카드, 점수 화면."

## 범위

**포함**: 차량(에뮬레이터 포함)의 속도, 기어(주차 여부), 주행 제한 상태를 읽어 엔진이 쓰는 신호로 바꿔 공급하는 실차 신호 소스, 신호를 받을 수 없을 때의 안전한 처리, 실차 신호 모드와 데모 모드의 구분과 전환, 신호 상태를 개발자가 확인하는 방법.

**제외 (별도 기능)**: 말풍선과 음성(TTS), 이름 짓기 온보딩과 외형 선택 화면, 도착 리포트와 하이라이트 리플레이 화면, 둥둥이와 멀티 윈도우 카드, 점수 화면. 속도, 기어, 주행 제한 외의 신호(방향지시등, 브레이크 페달, 방위각, 차선 이탈·충돌 같은 경고)는 이번 범위에 넣지 않는다(가정 참고).

**기존 기능과의 관계**: 엔진, 펫 화면, `MockSignalSource` 데모는 그대로 둔다. 엔진은 신호가 목업에서 오는지 실차에서 오는지 구분하지 않으므로, 엔진 이후 동작은 바뀌지 않아야 한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 플랫폼의 주행 제한 상태에 따라 펫이 움직이거나 정적으로 바뀐다 (Priority: P1)

운전자(또는 개발자)가 앱을 열어 둔 상태에서 차량 플랫폼이 알려주는 주행 제한 상태가 바뀌면, 펫이 그 상태를 따라 즉시 정적 표현으로 바뀌거나 풀 모션으로 돌아간다. 데모의 수동 "제한 있음/없음" 토글 없이 실제 차량 상태만으로 동작한다.

**Why this priority**: 이 앱의 1순위 원칙은 플랫폼이 알려주는 주행 제한 상태를 따르는 것이다(헌장 I). 이 연결이 없으면 앱은 항상 "알 수 없음"으로 간주돼 영원히 정적으로만 보이고, 주행 중 시선 분산을 막는 핵심 안전 규칙도 실차에서 검증할 수 없다.

**Independent Test**: 에뮬레이터에서 앱을 실차 신호 모드로 열고, Virtual Console에서 기어를 P와 D로 바꿔 가며(규제 켬/끔 명령 포함) 펫 화면과 디버그 정보가 제한 상태에 맞게 바뀌는지 본다. 데모 재생이나 수동 토글은 쓰지 않는다.

**Acceptance Scenarios**:

1. **Given** 앱이 실차 신호 모드로 열려 있고 플랫폼이 "제한 없음"을 알린 상태다, **When** 플랫폼이 "제한 있음"으로 바꾼다, **Then** 펫이 1초 안에 모든 움직임을 멈추고 정적 표현으로 바뀐다.
2. **Given** 정적 표현 중이고 플랫폼이 "제한 있음"이다, **When** 플랫폼이 "제한 없음"으로 바꾼다, **Then** 펫이 풀 모션으로 돌아간다.
3. **Given** 앱이 막 열렸고 플랫폼의 제한 상태를 아직 받지 못했다, **When** 첫 상태가 오기 전까지, **Then** 펫은 "알 수 없음"으로 취급해 정적 표현만 보여준다.
4. **Given** 같은 제한 상태가 반복해서 통지된다, **When** 상태 값이 바뀌지 않았다, **Then** 펫 표현이 바뀌거나 깜빡이지 않는다.
5. **Given** 속도가 낮거나 0이다, **When** 플랫폼이 여전히 "제한 있음"이다, **Then** 펫은 속도를 근거로 제한을 풀지 않고 정적으로 유지한다(속도와 기어는 제한 판단에 쓰지 않는다).

### User Story 2 - 차량의 속도와 기어 변화가 엔진 신호로 전달된다 (Priority: P1)

차량의 속도와 기어(주차 여부)가 바뀌면 그 값이 엔진이 쓰는 속도 신호와 주차 상태 신호로 전달된다. 에뮬레이터의 Virtual Console에서 기어를 바꾸면 엔진이 그에 맞는 주행 상태(주차, 주행 중)로 바뀐다.

**Why this priority**: 엔진이 주행 시작, 도착 같은 생명주기와 감정을 판단하려면 속도와 주차 상태가 필요하다. 제한 상태(스토리 1)와 함께 있어야 "실제 차량 상태에 따라" 동작한다고 말할 수 있다.

**Independent Test**: 앱을 실차 신호 모드로 열고 Virtual Console에서 기어를 P, D, R, N으로 순서대로 바꾸면서, 엔진이 받은 주차 여부와 속도 값을 디버그 정보에서 확인한다.

**Acceptance Scenarios**:

1. **Given** 기어가 P다, **When** 기어를 D로 바꾼다, **Then** 엔진이 받는 주차 상태가 "주차 아님"으로 바뀐다. 다시 P로 바꾸면 "주차"로 바뀐다.
2. **Given** 차량 속도가 바뀌고 있다, **When** 새 속도 값이 오면, **Then** 엔진이 받는 속도(m/s)가 그 값으로 갱신된다.
3. **Given** 차량이 km/h로 알려주든 m/s로 알려주든, **When** 속도가 전달된다, **Then** 엔진에는 항상 m/s로 들어가고 음수나 비정상 값은 엔진에 들어가지 않는다.
4. **Given** 앱이 열린 시점에 기어가 이미 D다, **When** 신호 수신을 시작한다, **Then** 현재 기어 값이 바로 한 번 전달된다(변화가 생기기를 기다리지 않는다).
5. **Given** 신호가 여러 종류에서 거의 동시에 온다, **When** 엔진으로 전달된다, **Then** 시각이 감소하는 순서로 전달되지 않는다.

### User Story 3 - 신호를 받을 수 없을 때 안전하게 정적으로 떨어진다 (Priority: P1)

권한이 없거나, 차량 서비스에 연결되지 않았거나, 해당 신호를 지원하지 않거나, 연결이 중간에 끊겨도 앱은 죽지 않는다. 제한 상태를 알 수 없으면 "알 수 없음"으로 보고 펫은 정적으로만 보인다.

**Why this priority**: 제한 상태를 모를 때 풀 모션을 내보내면 주행 중 시선 분산으로 심사 반려와 안전 문제가 된다. "모르면 정적"이 안전 쪽 기본값이다(헌장 I, `UNKNOWN` 은 제한으로 취급).

**Independent Test**: 권한을 막거나 차량 서비스를 끈 상태, 신호 지원이 없는 환경에서 앱을 열어, 앱이 종료되지 않고 펫이 정적이며 이유가 디버그 정보에 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필요한 권한이 허용되지 않았다, **When** 앱이 실차 신호 모드로 열린다, **Then** 앱은 종료되지 않고 제한 상태는 "알 수 없음"이며 펫은 정적이다.
2. **Given** 실행 중에 차량 서비스 연결이 끊긴다, **When** 끊김이 감지된다, **Then** 제한 상태가 "알 수 없음"으로 바뀌어 펫이 정적으로 바뀐다. 연결이 복구되면 현재 값을 다시 받아 정상 동작으로 돌아간다.
3. **Given** 차량이 속도나 기어 중 일부만 지원한다, **When** 지원하지 않는 신호가 있다, **Then** 그 신호만 생략하고 나머지는 정상 전달한다(차종명으로 분기하지 않고 지원 여부 확인으로 판단한다).
4. **Given** 제한 상태가 오랫동안 바뀌지 않았고 연결은 정상이다(플랫폼은 값이 변할 때만 통지한다), **When** 시간이 지난다, **Then** 마지막으로 받은 값을 그대로 유지하고(시간이 지났다는 이유로 "알 수 없음"으로 바꾸지 않는다), 진단 정보에는 연결 상태가 "정상"으로 보이며 마지막 갱신 시각이 표시된다.

### User Story 4 - 실차 신호 모드와 데모 모드를 오가도 서로 섞이지 않는다 (Priority: P2)

앱 홈에서 실차 신호로 동작하는 모드와 기존 데모(목업 시나리오 재생, 수동 제한 토글) 모드를 구분해 쓸 수 있다. 영상 촬영에는 데모를, 실제 확인에는 실차 신호를 쓴다. 두 소스의 신호가 동시에 엔진에 들어가 섞이지 않는다.

**Why this priority**: 11/15 영상 촬영은 데모 시나리오가 필요하고(002 스펙), 실차 확인은 실차 신호가 필요하다. 둘을 오가는 길이 없으면 한쪽 개발이 다른 쪽을 막는다. 다만 신호 연결 자체(스토리 1~3)보다 후순위다.

**Independent Test**: 실차 신호 모드에서 데모 모드로 전환해 시나리오를 재생하고, 다시 실차 모드로 돌아와 기어를 바꿨을 때 앞서 재생하던 시나리오의 영향이 남지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 실차 신호 모드다, **When** 데모 모드로 전환한다, **Then** 실차 신호 수신이 멈추고 데모 재생 화면과 수동 제한 토글이 기존처럼 동작한다.
2. **Given** 데모 모드에서 시나리오가 재생 중이다, **When** 실차 신호 모드로 전환한다, **Then** 시나리오 재생이 멈추고 엔진 상태가 초기화되며 실차의 현재 값부터 새로 시작한다.
3. **Given** 실차 신호 모드다, **When** 화면 회전이나 크기 변경이 일어난다, **Then** 모드와 신호 수신이 끊기지 않고 이어진다.
4. **Given** 실차 신호 모드다, **When** 현재 신호 상태를 확인하고 싶다, **Then** 현재 모드, 제한 상태, 속도, 기어(주차 여부), 연결 상태를 개발자가 볼 수 있다.

---

### User Story 5 - 앱이 쓰이지 않을 때 신호 수신을 멈추고 자원을 돌려준다 (Priority: P2)

앱이 화면에 보이지 않거나 종료되면 차량 신호 수신을 멈추고, 다시 보이면 현재 값부터 다시 시작한다. 차량 서비스 연결이 새거나 백그라운드에서 불필요하게 일하지 않는다.

**Why this priority**: 심사 기준에 CPU(주행 중 5% 미만)와 백그라운드 사용 최소화가 있고, 차량 서비스 연결은 해제하지 않으면 누수가 된다. 동작 자체가 아니라 품질 조건이라 P2다.

**Independent Test**: 앱을 열었다 홈으로 보내고 다시 연 뒤, 보이지 않는 동안 신호 수신이 없고 돌아오면 현재 값이 한 번 전달되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 실차 신호 모드로 열려 있다, **When** 앱이 화면에서 사라진다(백그라운드, 종료 포함), **Then** 모든 신호 수신이 멈추고 차량 서비스 연결이 정리된다.
2. **Given** 앱이 백그라운드에 있었다, **When** 다시 화면에 보인다, **Then** 현재 속도, 기어, 제한 상태를 한 번씩 받아 엔진이 최신 상태에서 시작한다.
3. **Given** 앱이 반복해서 열리고 닫힌다, **When** 20회 반복한다, **Then** 수신 중인 연결이나 리스너가 누적되지 않는다.

---

### Edge Cases

- 제한 상태가 앱 시작 직후, 첫 화면 그리기보다 먼저 또는 나중에 도착하면? 도착 전까지는 "알 수 없음"(정적)이고, 늦게 와도 그 시점에 정상 반영한다.
- 속도가 아주 짧은 간격으로 쏟아지면? 엔진이 감당할 수 있는 빈도로 줄여 전달하고, 값의 순서와 시각은 유지한다.
- 차량이 속도 단위를 km/h로 줄 때 반올림 오차로 0 근처에서 미세한 음수가 나오면? 0으로 보정하거나 버리고, 엔진에 음수가 들어가지 않는다.
- 기어가 R, N처럼 P도 D도 아닌 값이면? "주차 아님"으로 전달한다. 기어 값을 알 수 없으면 주차 상태 신호를 보내지 않는다.
- 같은 시각에 속도, 기어, 제한 신호가 함께 오면? 시각이 같은 것은 허용하되 감소하지는 않는다.
- 데모 모드의 수동 제한 토글은 실차 모드에서 어떻게 보이나? 실차 모드에서는 보이지 않거나 비활성이어서 실차 상태를 덮어쓸 수 없다.
- 지역(한국, 북미, 유럽)에 따라 제한 규칙이 다르면? 앱은 지역을 구분하지 않고 플랫폼이 알려주는 제한 상태만 따른다(규칙은 플랫폼이 적용한다).
- 에뮬레이터 이미지가 제한 상태 통지를 지원하지 않으면? "알 수 없음"으로 남아 정적이며, 이는 정상 동작이고 디버그 정보에 이유가 보여야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 엔진이 쓰는 신호 소스 약속을 그대로 지키는 실차 신호 소스를 제공해야 한다. 엔진은 소스가 목업인지 실차인지 구분하지 못해야 한다.
- **FR-002**: 시스템은 플랫폼이 알려주는 주행 제한 상태("있음", "없음")를 제한 신호로 엔진에 전달해야 하며, 제한 상태가 바뀌면 바뀐 시점의 값을 전달해야 한다.
- **FR-003**: 시스템은 제한 상태를 아직 받지 못했거나, 읽을 수 없거나, 연결이 끊겼으면 "알 수 없음"을 엔진에 전달해야 하고, 엔진은 이를 제한이 있는 것으로 취급해야 한다.
- **FR-004**: 시스템은 속도와 기어(주차 여부)로 제한 상태를 판단하거나 덮어써서는 안 된다. 제한 판단은 플랫폼이 알려주는 제한 상태가 유일한 근거다. 속도와 기어는 엔진의 주행 상태 판단용 보조 신호로만 전달한다.
- **FR-005**: 시스템은 차량 속도를 m/s 단위의 0 이상 유한한 값으로 바꿔 속도 신호로 전달해야 한다. 음수, NaN, 무한대 값은 엔진에 전달하지 않는다.
- **FR-006**: 시스템은 차량 기어가 P면 "주차", 그 밖의 알려진 값이면 "주차 아님"으로 주차 상태 신호를 전달해야 한다. 기어를 알 수 없으면 주차 상태 신호를 보내지 않는다.
- **FR-007**: 시스템은 신호 수신을 시작할 때 속도, 기어, 제한 상태의 현재 값을 각각 한 번씩 읽어 전달해야 한다. 변화가 생기기를 기다려서는 안 된다.
- **FR-008**: 시스템은 같은 스트림 안의 모든 신호 시각이 감소하지 않도록 해야 하며, 시각은 벽시계가 아니라 단조 증가하는 기준으로 만들어야 한다.
- **FR-009**: 시스템은 신호가 없는 구간에서도 엔진이 시간을 진행할 수 있도록 시간 진행 신호(Tick)를 주기적으로 전달해야 한다.
- **FR-010**: 시스템은 필요한 권한이 허용되지 않았거나, 차량 서비스에 연결할 수 없거나, 개별 신호를 지원하지 않아도 종료되거나 예외로 멈추면 안 된다. 지원하지 않는 신호는 생략하고 나머지는 정상 전달한다.
- **FR-011**: 시스템은 개별 신호의 지원 여부를 차종명이나 플랫폼 이름이 아니라 차량 서비스가 알려주는 지원 여부 확인으로 판단해야 한다. 지역(`KOR`, `EUR`, `USA`, `CAN`)에 따른 분기를 두지 않는다.
- **FR-012**: 시스템은 차량 서비스 연결이 끊기면 제한 상태를 "알 수 없음"으로 바꾸고, 연결이 복구되면 현재 값을 다시 읽어 정상 동작으로 돌아와야 한다.
- **FR-013**: 시스템은 앱이 화면에서 사라지거나 종료될 때 신호 수신을 멈추고 차량 서비스 연결과 수신 등록을 정리해야 한다. 정리한 인스턴스를 다시 쓰지 않고, 다시 시작할 때는 새로 만든다.
- **FR-014**: 시스템은 차량 서비스의 응답과 수신 통지가 어느 스레드에서 오든 엔진과 화면 상태를 안전하게 갱신해야 한다(스레드가 문서에 명시되지 않음). 화면 갱신은 메인 스레드에서만 한다.
- **FR-015**: 시스템은 실차 신호 모드와 데모 모드를 구분하고, 한 번에 하나의 소스만 엔진에 연결해야 한다. 모드를 바꿀 때 이전 소스의 수신을 멈추고 엔진 상태를 초기화한다.
- **FR-016**: 시스템은 실차 신호 모드에서 데모의 수동 제한 토글과 시나리오 재생이 엔진 입력에 영향을 주지 못하게 해야 한다.
- **FR-017**: 시스템은 개발자가 현재 모드, 제한 상태, 속도, 기어(주차 여부), 연결 상태와 신호를 받지 못하는 이유를 확인할 수 있는 정보를 제공해야 한다.
- **FR-018**: 시스템은 화면 회전과 크기 변경 중에도 모드와 신호 수신을 이어가야 한다.
- **FR-019**: 시스템은 실제로 쓰는 신호에 필요한 권한만 최소로 요청해야 하며, 승인되지 않은 권한은 선언하거나 호출하지 않는다.
- **FR-020**: 시스템은 차량 하드웨어나 센서에 직접 접근하지 않고, 표준 데이터는 플랫폼 표준 차량 API로만 읽어야 한다. 클러스터와 같은 속도는 위치 기반(GPS)이 아니라 차량 속도 값으로 얻는다.
- **FR-021**: 시스템은 실차 신호의 변환 규칙(단위, 기어와 주차 여부, 제한 상태 매핑, 시각 부여)을 차량 없이 검증할 수 있도록, 차량 서비스 접근과 변환 규칙을 분리해야 한다.
- **FR-022**: 시스템은 기존 `MockSignalSource` 기반 데모(시나리오 재생, 수동 제한 토글)와 002 스펙의 펫 동작을 그대로 유지해야 한다.

### Key Entities

- **실차 신호 소스**: 차량에서 속도, 기어, 제한 상태를 읽어 시각이 붙은 신호 스트림으로 내보내는 것. 시작과 정지가 있고, 정지하면 모든 수신이 멈춘다.
- **신호 모드**: 앱이 지금 신호를 어디서 받는지(실차 또는 데모). 한 번에 하나만 활성이다.
- **연결 상태**: 차량 서비스와의 연결이 정상인지, 끊겼는지, 권한이나 지원 문제로 쓸 수 없는지. 제한 상태 판단과 디버그 정보에 쓴다.
- **제한 상태**: 플랫폼이 알려주는 주행 제한("있음", "없음") 또는 알 수 없음. 알 수 없음은 제한이 있는 것으로 취급한다.
- **신호 진단 정보**: 개발자가 볼 수 있는 현재 모드, 제한 상태, 속도, 기어, 연결 상태, 신호를 받지 못하는 이유.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 에뮬레이터에서 주행 제한 상태를 바꾸면(규제 켬/끔, 기어 변경) 1초 안에 펫이 정적과 풀 모션 사이에서 바뀐다. 10회 반복해 모두 통과한다.
- **SC-002**: 실차 신호 모드에서 제한 상태를 받기 전, 권한 없음, 서비스 연결 실패, 연결 끊김 중 어느 경우에도 펫이 풀 모션으로 움직인 프레임이 0이다.
- **SC-003**: Virtual Console에서 기어를 P, D, R, N으로 바꾸면 엔진이 받는 주차 상태가 매번 기대한 값(P만 주차)으로 바뀌고, 4가지 모두 통과한다.
- **SC-004**: 속도와 기어를 어떤 순서로 바꿔도 제한 상태가 속도나 기어에서 영향을 받지 않는다. 속도 0이고 P단이어도 플랫폼이 "제한 있음"이면 펫은 정적이다.
- **SC-005**: 권한 거부, 서비스 없음, 신호 미지원 세 환경에서 앱이 한 번도 종료되지 않고 열리며, 각각 이유가 진단 정보에 표시된다.
- **SC-006**: 변환 규칙(속도 단위, 기어와 주차 여부, 제한 상태 매핑, 음수와 비정상 값 거부, 시각 비감소) 검증이 차량 없이 자동으로 실행되고 모두 통과한다.
- **SC-007**: 앱을 20회 열고 닫은 뒤에도 수신 등록과 서비스 연결이 누적되지 않고, 화면에 보이지 않는 동안 신호 수신이 0건이다.
- **SC-008**: 데모 모드의 시나리오 재생과 수동 제한 토글이 변경 전과 똑같이 동작하고, 기존 자동 테스트(001, 002)가 모두 통과한다.
- **SC-009**: 모드를 10회 번갈아 전환해도 이전 모드의 신호가 엔진에 섞여 들어오는 경우가 0이다.

## Assumptions

- 이번 범위의 신호는 속도, 기어(주차 여부), 주행 제한 상태 세 가지다. 방향지시등, 브레이크 페달, 방위각, 경고 신호는 엔진에서 감정 이벤트를 만드는 데 쓰이지만 이번에는 연결하지 않고, 해당 이벤트는 실차 모드에서 나오지 않는다. 필요하면 별도 기능으로 이어서 추가한다.
- 속도, 기어, 제한 상태는 플랫폼 표준 차량 API로 읽는다. 표준 API 사용 허용 여부는 대회 측 확인 전이라 `[확인 필요]` 이며(헌장 IV), 허용되지 않으면 같은 신호 소스 약속 뒤에서 Pleos Vehicle SDK로 바꾼다. 어느 쪽이든 엔진 이후 코드는 바뀌지 않는다.
- 개발과 검증 환경은 Pleos Connect 에뮬레이터(API 34)와 Virtual Console이다. 에뮬레이터 이미지가 위 세 신호를 실제로 내는지는 `[확인 필요]` 이며, 내지 않으면 해당 신호는 "알 수 없음"으로 남는다(스토리 3).
- 기어 값에 따른 주차 판단은 P만 주차로 본다. 주차 브레이크나 Auto Hold는 이번에 쓰지 않는다.
- 제한의 해제 조건(시동 OFF, 5 km/h 이하와 정지 등)은 플랫폼이 판단해 알려주는 값을 그대로 따르며, 앱이 다시 계산하지 않는다.
- 앱은 열릴 때 실차 신호 모드가 기본이고, 데모 모드는 기존 데모 화면의 진입 방식을 유지한다. 모드 선택 방식의 세부 UI는 계획 단계에서 정한다.
- 속도 통지는 차량이 정한 주기를 따르며, 앱이 별도로 높은 빈도를 요구하지 않는다.
- 차량 서비스 응답과 통지의 스레드는 문서에 명시가 없어 `[확인 필요]` 이며, 어느 스레드에서 와도 안전하도록 만든다.
- 모듈 경계(`:app` → `:pet` → `:engine` → `:signal`)와 SDK 호출 위치(`:signal` 에만)는 헌장 II를 따른다.
- 검증 결과는 002와 같이 에뮬레이터 확인 방법과 결과를 `checklists/verification-log.md` 에 남긴다.
