# 수동 확인 기록 (T052, T073)

에뮬레이터 또는 프리뷰가 필요한 항목이다. 실행: `./gradlew :app:installDebug` 후 `adb shell am start -n com.example.dashpet/.MainActivity`.

## 환경

- 에뮬레이터: AVD `Pleos_Connect_v2.1.0`(API 34, `crp_avd_arm64`, 해상도 2560x1440), Cold boot(`-no-snapshot-load -no-snapshot-save`), 부팅 약 14초.
- 2026-11-08, Mac(Apple Silicon)에서 확인. 앱은 `:app:installDebug`(디버그 빌드)로 설치.
- 화면 구성: 왼쪽 클러스터(주행 정보), 오른쪽 앱 영역(DashPet), 하단 GNB.

## 발견한 문제와 관찰

1. **재생이 설계보다 느리고 표시 시각이 어긋난다.** 패널 시각이 실제 경과 시간의 약 85~90%로 흐른다(스크립트 15초 → 표시 0:13, 47초 → 0:41). `MockSignalSource`(REAL_TIME)의 상대 `delay`와 `DemoViewModel` 경과 타이머(`delay(100)` 루프)가 각각 반복마다 지연을 누적하고 서로 독립이라서, 이벤트 시각, 표시 시각, 실제 시간이 모두 어긋난다. 영상이 설계(55초)보다 길어진다.
2. **컨트롤이 작다.** 2560x1440 화면에서 컨트롤 버튼과 패널 글자가 매우 작게 보인다(글자는 12sp 이상이지만 차량 화면 기준으로 터치 대상이 작다). Pleos UI 가이드는 큰 터치 대상을 요구한다.
3. **앱이 가려졌다 돌아오면 상태가 초기화된다.** 위 J 참고. 이 데모 화면에서는 문제가 아니지만 제품 화면에서는 상태 저장 전략이 필요하다(설계 가이드: 프로세스 재생성에도 진행 상태 복원).

## 주의

- 에뮬레이터 창은 사용자의 화면에 열려 있어 사람이 직접 만질 수 있다. 자동 캡처 중에 조작하면 결과가 어긋난다. 재촬영할 때는 에뮬레이터를 건드리지 않는다.
- 스크린샷은 `/tmp/dashpet_shots/`(임시)에 있고 저장소에는 올리지 않았다.
