# Feature Specification: 주행 이벤트 판정과 펫 감정 결정 코어

**Feature Branch**: `001-driving-event-core`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: "SDK 연결 전에 구현할 수 있는 것부터 시작한다. 차량 신호(속도, 방향, 브레이크, 방향지시등, 경고)를 받아 급가속·급제동·급커브·경고·차선 변경 이벤트를 판정하고, 펫의 감정 상태와 주행 점수를 정하고, 주행 제한 상태에 따라 표현 수위(모션 등급)를 결정하는 코어를 만든다. 목업 시나리오로 반복 검증한다. (11/15 프로토타입 범위: 물리 반응, 경고 번역, 깜빡이 윙크)"

## 범위

**포함**: 신호 → 이벤트 판정, 이벤트 → 펫 감정 상태, 주행 제한 상태 → 모션 등급, 주행 점수 계산, 주행 기록, 목업 시나리오 재생.

**제외 (별도 기능으로 분리)**: 캐릭터 그리기와 물리 표현, 음성(TTS) 출력과 대사, 이름 짓기 온보딩, 도착 리포트 화면, 실제 차량 SDK 연결, 서버 동기화, LLM 대화.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 급가속·급제동·급커브에 펫이 반응한다 (Priority: P1)

운전자가 급하게 가속하거나 멈추거나 꺾으면, 내 차 펫이 그 순간의 쏠림을 반응으로 보여줄 수 있도록 시스템이 "급가속", "급제동", "급커브"를 정확히 구분해서 판정하고 세기와 방향을 알려준다.

**Why this priority**: 데모와 1차 심사의 핵심 장면(물리 반응)이 이 판정에 달려 있다. 판정이 틀리면 캐릭터가 엉뚱한 때 반응하거나 반응하지 않는다.

**Independent Test**: 속도와 진행 방향 신호만 넣어서 이벤트 목록을 확인한다. 다른 기능 없이도 "이 신호 흐름에서 급제동 1회, 급커브 1회"를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 50km/h로 달리는 중, **When** 2초 동안 0km/h까지 감속하고 브레이크 페달이 눌려 있다, **Then** 급제동 이벤트가 1회 발생하고 방향은 "앞"이며 세기는 0~1 사이 값이다.
2. **Given** 50km/h로 달리는 중, **When** 1초 동안 진행 방향이 30도 바뀐다, **Then** 급커브 이벤트가 1회 발생하고 방향은 꺾은 쪽 반대편 벽으로 쏠리는 방향(좌/우)이다.
3. **Given** 0km/h에서 50km/h까지 8초 동안 완만하게 가속한다, **When** 신호를 처리한다, **Then** 급가속 이벤트는 발생하지 않는다.
4. **Given** 시속 15km/h 미만으로 움직이는 중, **When** 진행 방향이 크게 바뀐다, **Then** 급커브 이벤트는 발생하지 않는다.

---

### User Story 2 - 차량 경고를 펫의 감정으로 번역한다 (Priority: P1)

차량이 차선 이탈이나 충돌·근접 경고를 낼 때, 펫이 어지러워하거나 깜짝 놀라는 감정으로 바뀌고, 더 중요한 감정이 덜 중요한 감정에 밀리지 않는다. 차량의 원래 경고는 그대로 두고 그 위에 얹는 표현이다.

**Why this priority**: 경고 번역은 앱의 정체성("경고를 감정으로")이자 핵심 3장면 중 하나다.

**Independent Test**: 경고 신호와 이벤트만 넣어서 감정 상태의 변화(어떤 감정, 얼마 동안, 언제 편안으로 복귀)를 확인한다.

**Acceptance Scenarios**:

1. **Given** 펫이 편안 상태, **When** 차선 이탈 경고가 켜진다, **Then** 펫은 "어지러움" 상태가 되고 3초 뒤 편안으로 돌아간다.
2. **Given** 펫이 어지러움 상태, **When** 충돌 위험 경고가 켜진다, **Then** 더 높은 우선순위인 "깜짝" 상태로 즉시 바뀐다.
3. **Given** 펫이 깜짝 상태, **When** 급제동(더 낮은 우선순위)이 발생한다, **Then** 감정은 바뀌지 않고 그 반응은 대기열에 쌓이지 않고 버려진다.
4. **Given** 펫이 찌그러짐 상태, **When** 같은 우선순위의 새 이벤트가 들어온다, **Then** 즉시 전환되고 지속 시간이 새로 시작된다.

---

### User Story 3 - 주행 제한 상태에 따라 표현 수위를 낮춘다 (Priority: P1)

차량이 "주행 제한" 상태이면(주행 중, 정차 중, 상태를 알 수 없음 포함) 시스템은 정적인 표현만 쓰라고 알려주고, 제한이 풀린 주차·정지 상태에서만 풀 모션을 허용한다. 상태가 바뀌면 바로 반영한다.

**Why this priority**: 이 앱의 공모 분야가 "안전 운전"이고, 심사 반려 1순위가 주행 중 시선 분산이다. 헌장의 비협상 원칙이기도 하다.

**Independent Test**: 제한 상태(없음/있음/알 수 없음)를 바꿔 가며 같은 이벤트를 넣고, 매번 출력되는 모션 등급을 확인한다.

**Acceptance Scenarios**:

1. **Given** 제한이 풀린 상태(주차·정지), **When** 이벤트가 발생한다, **Then** 풀 모션 등급으로 알려준다.
2. **Given** 제한이 걸린 상태(정차 중 또는 주행 중), **When** 이벤트가 발생한다, **Then** 정적 등급으로만 알려준다.
3. **Given** 제한 상태를 알 수 없다, **When** 이벤트가 발생한다, **Then** 제한이 걸린 것으로 취급한다.
4. **Given** 풀 모션 진행 중, **When** 제한이 걸린다, **Then** 그 다음 출력부터 정적 등급으로 바뀐다.
5. **Given** 일회성 짧은 전환(B 등급) 설정이 꺼져 있다(기본값), **When** 제한 중 이벤트가 발생한다, **Then** B 등급은 출력되지 않는다.

---

### User Story 4 - 주행 점수와 기록을 남긴다 (Priority: P2)

주행이 끝나면 오늘 점수를 알 수 있도록, 모든 이벤트에 가점과 감점을 매기고 주행 기록에 남긴다. 감정이 바뀌지 않는 이벤트도 점수와 기록에는 반영한다.

**Why this priority**: 도착 리포트와 성장 시스템의 기반이지만, 프로토타입 핵심 장면은 점수 없이도 성립한다.

**Independent Test**: 이벤트 목록을 넣고 최종 점수와 기록을 확인한다.

**Acceptance Scenarios**:

1. **Given** 100점으로 시작한 주행에서 벨트 체결(+2), 깜빡이 켠 차선 변경(+1), 급커브(-2), 차선 이탈(-5), 급제동(-2)이 일어난다, **When** 주행이 끝난다, **Then** 최종 점수는 94점이다.
2. **Given** 깜빡이 켠 차선 변경 가점이 이미 +5에 도달했다, **When** 또 깜빡이 켠 차선 변경이 일어난다, **Then** 가점은 더 오르지 않는다.
3. **Given** 감점 이벤트가 연속으로 많이 쌓여 합이 -100을 넘는다, **When** 최종 점수를 계산한다, **Then** 0점으로 자른다(합산 중에는 자르지 않는다).
4. **Given** 깜빡이 없이 차선 변경이 일어난다, **When** 이벤트를 처리한다, **Then** 펫 감정은 바뀌지 않고 -3점과 기록만 남는다.

---

### User Story 5 - 목업 시나리오로 반복 검증하고 시연한다 (Priority: P2)

실제 차량 연결 전에 정해진 주행 시나리오(시간대별 신호)를 재생해서 같은 결과를 반복해서 얻을 수 있다. 개발자는 이것으로 검증하고, 시연 영상도 여러 번 찍어 가장 좋은 장면을 고른다.

**Why this priority**: 실차 신호와 에뮬레이터 데이터 주입이 모두 불확실하므로, 목업이 없으면 개발과 11/15 영상이 막힌다.

**Independent Test**: 데모 출근 시나리오를 재생해서 기대 이벤트 순서와 점수를 확인한다.

**Acceptance Scenarios**:

1. **Given** 데모 출근 시나리오(주차 브레이크 해제 → 벨트 경고 해제 → 가속 → 급커브 → 깜빡이 차선 변경 → 차선 이탈 경고 → 급제동 → 주차 브레이크 채움), **When** 재생한다, **Then** 이벤트가 출발, 벨트 체결, 급커브, 좋은 차선 변경, 차선 이탈, 급제동, 도착 순서로 나오고 점수는 94점이다.
2. **Given** 같은 시나리오, **When** 100번 재생한다, **Then** 모든 결과가 같다.
3. **Given** 속도와 방향이 "서서히 변하는 구간"으로 적힌 시나리오, **When** 재생한다, **Then** 실제 신호처럼 초당 10번의 값으로 풀어서 전달된다.

---

### User Story 6 - 방향지시등 상태를 펫에 전달한다 (Priority: P3)

방향지시등이 켜져 있는 동안 펫이 같은 쪽 눈으로 윙크할 수 있도록, 방향지시등 상태(좌/우)를 이벤트와 별개로 알려준다.

**Why this priority**: 감성 요소이고 판정 로직에 영향이 적다.

**Independent Test**: 방향지시등 상태만 바꿔 넣고 전달되는 상태를 확인한다.

**Acceptance Scenarios**:

1. **Given** 방향지시등이 꺼져 있다, **When** 오른쪽이 켜진다, **Then** 차선 변경이 없어도 "오른쪽" 상태가 전달된다.
2. **Given** 오른쪽이 켜져 있다, **When** 꺼진다, **Then** "꺼짐" 상태가 전달된다.

---

### Edge Cases

- 신호 간격이 2초를 넘거나 속도 정보가 없는 샘플(터널, 신호 끊김)은 버리고, 그 샘플로는 가속도를 계산하지 않는다.
- 진행 방향이 359도에서 1도로 넘어갈 때는 +2도 변화로 계산한다(−180~180도로 정규화).
- 위치 신호의 순간 노이즈 때문에 이벤트가 튀지 않도록, 값을 평활화한 뒤 임계값을 2회 연속 넘을 때만 확정한다.
- 같은 종류의 이벤트가 짧은 시간에 반복되면 재발 간격 안에서는 한 번만 인정한다.
- 서로 다른 이벤트가 동시에 들어오면 감정 우선순위가 높은 쪽이 이긴다.
- 주행 시작 전에 들어온 벨트 경고 해제는 "벨트 체결" 이벤트로 치지 않는다(출발 이후 경고가 켜졌다가 꺼질 때만).
- 주차 상태여도 속도가 0이 아니면 도착으로 치지 않는다.
- 모든 이벤트(감정이 바뀌지 않는 것 포함)는 주행 기록에 남는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 다음 10가지 주행 이벤트를 판정해야 한다: 출발, 벨트 체결, 급가속, 급제동, 급커브, 차선 이탈, 충돌 위험, 좋은 차선 변경, 깜빡이 없는 차선 변경, 도착.
- **FR-002**: 급가속은 앞뒤 가속도가 +2.9 m/s²(약 0.3g) 이상일 때, 급제동은 −3.9 m/s²(약 0.4g) 이하이면서 브레이크 페달이 눌려 있을 때 확정해야 한다. 급커브는 옆 가속도가 3.9 m/s² 이상이고 속도가 15km/h 이상일 때 확정해야 한다. 이 값들은 초안이며 한 곳에서 바꿀 수 있어야 한다.
- **FR-003**: 옆 가속도는 속도와 진행 방향 변화율의 곱으로, 앞뒤 가속도는 속도 변화율로 계산해야 한다.
- **FR-004**: 속도와 진행 방향은 평활화(초안: 가중 0.4)를 거친 뒤 판정해야 하고, 임계값을 2회 연속 넘을 때만 이벤트를 확정해야 한다.
- **FR-005**: 신호 간격이 2초를 넘거나 속도 정보가 없는 샘플은 버려야 한다.
- **FR-006**: 각 이벤트는 세기(0~1)와 방향(좌/우/앞/뒤)을 함께 내보내야 한다.
- **FR-007**: 같은 종류 이벤트의 재발 간격은 급가속·급제동·급커브 3초, 차선 이탈·충돌 위험 10초, 차선 변경 평가 5초이고, 출발·벨트 체결·도착은 주행당 1회여야 한다.
- **FR-008**: 좋은 차선 변경과 깜빡이 없는 차선 변경은 차선 변경 시점 직전 3초 안에 같은 방향 방향지시등이 켜져 있었는지로 구분해야 한다.
- **FR-009**: 펫 감정은 편안(0), 배경 상태(1), 기쁨(2), 찌그러짐(3), 어지러움(4), 깜짝(5) 우선순위를 가져야 한다. 급가속·급제동·급커브는 찌그러짐, 차선 이탈은 어지러움, 충돌 위험은 깜짝, 벨트 체결·좋은 차선 변경·도착(점수 80 이상)은 기쁨으로 연결해야 한다.
- **FR-010**: 감정 지속 시간은 깜짝 3초, 어지러움 3초, 찌그러짐 1.2초, 기쁨 2초여야 하고, 끝나면 배경 상태(있으면) 또는 편안으로 돌아가야 한다.
- **FR-011**: 새 이벤트의 감정 우선순위가 현재와 같거나 높으면 즉시 전환하고 지속 시간을 새로 시작해야 한다. 낮으면 버려야 하며 대기열에 쌓으면 안 된다.
- **FR-012**: 깜빡이 없는 차선 변경은 감정을 바꾸지 않고 점수와 기록에만 반영해야 한다.
- **FR-013**: 모든 이벤트는 감정 전환 여부와 관계없이 주행 기록에 시각, 종류, 세기, 점수 변화와 함께 남아야 한다.
- **FR-014**: 주행 점수는 100점에서 시작해 차선 이탈 −5, 충돌 위험 −5, 깜빡이 없는 차선 변경 −3, 급가속·급제동·급커브 각 −2, 좋은 차선 변경 +1(주행당 최대 +5), 벨트 체결 +2를 반영하고, 모든 가감을 합산한 뒤 마지막에만 0~100으로 잘라야 한다.
- **FR-015**: 시스템은 주행 제한 상태(없음, 있음, 알 수 없음)를 입력으로 받아 모션 등급을 정해야 한다. 제한 없음은 풀 모션, 제한 있음과 알 수 없음은 정적이어야 한다.
- **FR-016**: 일회성 짧은 전환 등급은 설정으로 켠 경우에만 출력해야 하며 기본값은 꺼짐이어야 한다.
- **FR-017**: 주행 제한 상태가 바뀌면 그 다음 출력부터 새 모션 등급을 적용해야 한다.
- **FR-018**: 시스템은 감정, 강도, 방향, 모션 등급, 방향지시등 상태를 출력해야 한다(그리는 일은 이 기능의 범위가 아니다).
- **FR-019**: 방향지시등 좌/우 상태는 차선 변경 이벤트와 별개로 항상 전달해야 한다.
- **FR-020**: 시스템은 시간순으로 적힌 목업 시나리오(속도 변화, 방향 변화, 경고 켜짐/꺼짐, 방향지시등, 차선 변경, 브레이크 페달, 주차 브레이크)를 재생할 수 있어야 한다. 속도·방향의 연속 변화 구간은 초당 10회의 값으로 풀어서 전달해야 한다.
- **FR-021**: 같은 시나리오를 재생하면 항상 같은 이벤트와 점수가 나와야 한다.
- **FR-022**: 이벤트 판정, 감정, 점수 규칙은 신호가 목업에서 오는지 실제 차량에서 오는지 알지 못해야 한다.
- **FR-023**: 임계값, 재발 간격, 지속 시간, 점수 가중치는 한 곳에 모아 테스트에서 바꿀 수 있어야 한다.
- **FR-024**: 출발과 도착은 "주차 상태" 입력의 변화로 판정해야 한다. 주차 → 주차 아님은 출발이고, 주차 아님 → 주차이면서 속도가 0이면 도착이다. 주차 상태가 어디서 오는지(주차 브레이크, 기어, 시동 상태 등)는 이 기능이 알지 못한다.

### Key Entities *(include if feature involves data)*

- **원시 신호**: 시각이 붙은 차량 입력 하나. 속도와 방향, 주차 상태, 브레이크 페달, 방향지시등(꺼짐/좌/우), 차량 경고(종류와 켜짐 여부), 차선 변경 방향 중 하나.
- **주행 이벤트**: 판정 결과. 종류, 시각, 세기(0~1), 방향, 점수 변화.
- **펫 감정 상태**: 현재 감정, 강도, 쏠림 방향, 복귀 시각. 우선순위로 전환을 결정한다.
- **주행 기록(Trip)**: 한 번의 주행. 시작·종료 시각, 이벤트 목록, 최종 점수.
- **모션 등급**: 표현 수위 단계(정적, 일회성 전환, 풀 모션).
- **주행 제한 상태**: 없음, 있음, 알 수 없음 세 값.
- **시나리오**: 이름과 시간순 신호 목록. 목업 재생의 입력.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 데모 출근 시나리오를 재생하면 이벤트 7개가 정해진 순서로 나오고 최종 점수는 정확히 94점이다.
- **SC-002**: 같은 시나리오를 100번 반복 재생해도 이벤트 순서, 감정 전환, 점수가 100번 모두 같다.
- **SC-003**: 주행 제한이 걸린 상태에서 풀 모션 등급이 출력되는 경우는 0건이다(제한 상태 3가지 모두에서 검증).
- **SC-004**: 완만한 가속(약 1.7 m/s²)과 15km/h 미만의 방향 변화는 급가속·급커브로 오판정되지 않는다.
- **SC-005**: 이 문서의 모든 판정 규칙(임계값, 재발 간격, 우선순위, 점수)에 대응하는 자동 테스트가 있고, 차량이나 에뮬레이터 없이 10초 안에 전체가 실행된다.
- **SC-006**: 신호 출처를 목업에서 실제 차량으로 바꿔도 이벤트 판정, 감정, 점수 규칙은 수정하지 않는다.

## Assumptions

- 속도, 진행 방향, 주차 상태, 브레이크, 방향지시등, 경고, 차선 변경은 모두 입력 신호로만 다룬다. 실제 출처는 API 전수 조사 결과(`docs/api-inventory.md`, 로컬 전용)에 따라 별도 기능에서 정한다.
- 조사 결과에 따른 가정: 차량 속도는 Pleos SDK에 없어서 AAOS 표준 속도 값을 쓰는 방향이다(확정 전). 방향은 조향각이나 위치 방위각에서 얻는다. 방향지시등은 꺼짐/좌/우 세 값뿐이고 점멸 박자와 비상등은 제공되지 않는다.
- 차량 경고 중 공개 API로 얻을 수 있는 것은 안전벨트뿐이다. 차선 이탈, 충돌, 근접 경고와 차선 변경 이벤트는 실제 연결이 불확실하므로 11/15 프로토타입에서는 목업 입력으로만 검증한다.
- 주차 상태의 실제 출처(주차 브레이크, 기어, 시동 상태)는 일반 앱이 쓸 수 있는 공개 API가 제한적이라 미확정이다. 이 기능은 출처를 알지 못한다.
- 임계값과 점수 가중치는 초안이며, 테스트 주행 데이터를 본 뒤 조정한다.
- 주행 제한 상태는 "없음, 있음, 알 수 없음" 세 값으로 단순화해 입력받고, 이 값을 얻는 방법은 별도 기능에서 다룬다.
- 일회성 짧은 전환 등급은 심사 허용 여부가 확인되기 전까지 기본 꺼짐으로 둔다.
- 데모 시나리오의 속도 램프, 방위각 회전 값은 개발 명세서 9장의 시나리오를 따른다.
- 시간은 신호에 붙은 시각을 기준으로 하며 실제 시계에 의존하지 않는다.
- 감정 대사(음성), 색 표현, 캐릭터 그리기는 이 기능의 출력 값을 소비하는 다른 기능에서 정한다.
